## Per-device crop rejected on review; re-framed as device fit

Taylor read the crop test plan and rejected the approach: Media Library
cropping is for fixing the *source*, and how content meets a mismatched
screen is a *device* concern. Interviewed him to align, then wrote it
up.

- created [[decision-media-crop-vs-device-fit]] — fit modes (contain /
  fill-width / fill-height) owned by the device; v0.7.0's device-scope
  crop UI retires but its render pipeline is reused, since fill modes
  are computed crops. Quick-access fit dropdown in the device hover
  card when aspects disagree.
- created [[decision-viewing-geometry-tilt-and-falloff]] — per-stance
  screen tilt with an auto-orient checkbox (on for handheld/phone/
  tablet), all three stance heights editable at once, and per-point
  distance across a panel surfaced as a hover readout plus a toggleable
  falloff overlay. Reporting stays centre-referenced with an added
  "at that spot" figure, which keeps [[arc-minute-spreadsheet]]'s
  pinned rows intact.
- created [[plan-content-adaptation-nine-slice]] — the long-term model
  Taylor sketched: 9-slice borders and per-box response rules, i.e.
  simulating layout reflow instead of scaling a screenshot. Parked.
- Marked [[plan-per-device-crop]] superseded.

Useful find while digging: `contain` was ALREADY the fit behaviour
(recorded in [[review-2026-08-15-open-questions]]), so this adds the
missing choice rather than inventing a model.

## Device fit modes built

Finished the refactor [[decision-media-crop-vs-device-fit]] called for.
`Device.fit` (absent = contain) now drives a DERIVED crop in `lib/fit.ts`
— `fitCrop` composes over the item's source crop and stays normalized to
the full intrinsic image, so v0.7.0's texture clones, box culling and
report chips all feed off it untouched. `MediaItem.deviceCrops` and the
whole device-scope authoring layer are gone; the Media Library crop row
is back to editing the source only, exactly as before v0.7.0.

The one place the math cares behaved as the note predicted:
`boxMetricsOnDevice` now takes its scale from `fitScale(mode, …)` —
`Math.min` for contain, the width term for fill-width, the height term
for fill-height. Deliberately NOT `Math.max`; there is a test pinning
the case where the fill scale is the *smaller* ratio. The three pinned
[[arc-minute-spreadsheet]] rows (Switch Lite 20′, Switch 23′, 24″ 1080p
23′) pass unedited.

Fit controls: a full-width select in the Device Manager editor under
Curve, and a quick dropdown on the device hover card above "Edit in
Device Manager", rendered only when `aspectsDisagree` says the shapes
actually differ. Contain persists as `undefined`, so untouched devices
serialize byte-identically.

Gates: typecheck, lint, 128 tests, production build all green.
