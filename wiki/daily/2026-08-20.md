## Device fit modes built

Finished the refactor [[decision-media-crop-vs-device-fit]] called for.
`Device.fit` (absent = contain) now drives a DERIVED crop in `lib/fit.ts`
— `fitCrop` composes over the item's source crop and stays normalized to
the full intrinsic image, so v0.7.0's texture clones, box culling and
report chips all feed off it untouched. `MediaItem.deviceCrops` and the
whole device-scope authoring layer are gone; the Media Library crop row
is back to editing the source only, exactly as before v0.7.0.

The one place the math cares behaved as the note predicted:
`boxMetricsOnDevice` now takes its scale from `fitScale(mode, …)` —
`Math.min` for contain, the width term for fill-width, the height term
for fill-height. Deliberately NOT `Math.max`; there is a test pinning
the case where the fill scale is the *smaller* ratio. The three pinned
[[arc-minute-spreadsheet]] rows (Switch Lite 20′, Switch 23′, 24″ 1080p
23′) pass unedited.

Fit controls: a full-width select in the Device Manager editor under
Curve, and a quick dropdown on the device hover card above "Edit in
Device Manager", rendered only when `aspectsDisagree` says the shapes
actually differ. Contain persists as `undefined`, so untouched devices
serialize byte-identically.

## Screen auto-detection researched

Reconnaissance ahead of a possible "guess my screen size" onboarding
feature — no code changed. `getScreenDetails()` never returns physical
mm/inches on any engine, and it's Chromium-only with Firefox and
WebKit standards-positions issues still open (WebKit's flagged
`concerns: privacy`/`concerns: annoyance` since 2022). Resolution can
pin the exact device for Apple laptops/desktops/displays, the Switch
family, Steam Deck, and common phones/tablets, but is a wide, unreliable
guess for ordinary desktop monitors at 1080p/1440p/4K. Also found a
real gap: the repo's `dpr * screen.width / resolution.w` zoom-detection
trick (`calibration-dialog.tsx`, `display-area.tsx`, `scene-view.tsx`)
relies on Chrome/Safari freezing `screen.width` at 100%-zoom CSS px;
Firefox recomputes it live so the product is zoom-*invariant* there by
design (confirmed via a Mozilla engineer's comment on a still-open
Bugzilla issue) — the zoom warning would never fire in Firefox.

- created [[screen-auto-detection]] — full findings, resolution→device
  table, and the recommendation: confirm-not-silent prefill for
  device-exact matches, no prefill for ordinary monitors, calibration
  stays primary either way.
